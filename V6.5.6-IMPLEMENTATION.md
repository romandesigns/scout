# Scout v6.5.6 — Runtime Reliability + Self-Hosted ntfy

## Purpose

v6.5.6 addresses the production stall observed on 2026-08-17: the Scout process remained alive, consumed roughly one CPU core, stopped advancing Rust submissions, and eventually stopped answering `/healthz`.

## Changes

- Coalesces frontend dashboard refreshes and removes the full-dashboard refetch triggered by every SSE finding/chart event.
- Reduces routine Radar/catalyst/attention reconciliation payload sizes and pauses polling while the client is hidden.
- Adds short-lived server-side serialized-response caching for findings, catalysts, and attention to collapse duplicate request bursts.
- Serializes SIP/BOATS subscription reconciliation and gives every websocket subscription send a hard timeout.
- Tracks last market-event activity and reconciliation state in `/healthz`.
- Adds an independent event-loop watchdog thread. If the asyncio loop stops heartbeating beyond the threshold, Scout hard-exits so Docker `restart: unless-stopped` can recover it.
- Adds an ntfy 429 circuit breaker so a provider quota outage cannot create repeated retry work.
- Bundles a self-hosted ntfy Docker service with persistent cache. Deployments using `https://ntfy.sh` are migrated to the internal `http://ntfy:80` publisher endpoint.
- Detector recipes, Rust thresholds, lifecycle promotion logic, and scoring semantics are unchanged.

## Mobile ntfy note

Scout publishes to the self-hosted ntfy service internally. To receive those notifications in an ntfy mobile client, expose the ntfy service through your private Tailscale HTTPS endpoint and add that server URL to the ntfy app. Scout's native/PWA notification channels remain independent.
