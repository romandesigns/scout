# StockHunter Scout 6.2.0

## Timing contract

Scout intentionally separates four timestamps:

1. Formation window — the evidence interval being evaluated.
2. Detection — the exact engine timestamp and recorded market price.
3. Dispatch — the notification queue/provider timestamp.
4. Delivery — the recorded device/provider acceptance timestamp when available.

The detection line is never snapped to a candle center. The candle containing that timestamp is highlighted separately, and the audit overlay reports how many seconds into the candle detection occurred.

## Historical completeness

Alpaca historical trades are requested until `next_page_token` is exhausted. The snapshot exposes source, page count, trade count, and completeness. Minute bars remain the last fallback when no usable trades exist.

## Selection contract

Selecting an item in Radar, Ross, Catalysts, Gainers, Halts, Validation, or Opportunity Inbox updates Inspector. Items without a Scout finding receive an explicit contextual view stating that no detection is implied; stale Inspector content is never retained.

## Navigation counts

Each activity icon reports the current panel count, hides zero, caps display at `99+`, uses semantic color, and exposes panel name/count to tooltips and assistive technology.

## Native upgrade safety

Tauri uses the new `native-v2` WebView profile, which cannot load the legacy PWA service worker. Runtime migration unregisters any worker and reloads once only when stale cache entries actually exist.
