# Scout v6.6.5 — Detection-Quality Cohort Pipeline Fix

v6.6.5 fixes the empty ACTIONABLE forward-quality audit without changing the detector,
promotion thresholds, notification timing logic, or late-risk rules.

Root cause:
the audit fetched only the newest findings and then discarded anything younger than
the maturity threshold. Under live production throughput those newest rows were mostly
fresh C-rank observations, so mature A/B promotions were never present in the fetched
window.

Fix:
- `/api/findings` now supports `before=<unix timestamp>` and `actionable_only=1`.
- The quality audit asks the server directly for already-mature A/B findings.
- The report now includes fetched/selected counts and explicit exclusion reasons.
- Existing snapshot-based independent forward-return recomputation remains unchanged.
- Regression tests reproduce the previous starvation case and verify a synthetic EARLY
  promoted finding yields measurable 5m/15m forward metrics.
