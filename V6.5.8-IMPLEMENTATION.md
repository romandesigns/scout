# Scout v6.5.8 — Hybrid backpressure throughput

This release targets the production saturation observed with a full 50,000-event Python→Rust bridge queue and rising dropped-event counters.

## Changes

- Preserve the existing `scout.market-event.v1` JSONL contract and event ordering.
- Drain the bridge queue in ordered micro-batches and perform one asyncio pipe write/drain per batch instead of per trade.
- Add bridge throughput telemetry: `written`, `writer_batches`, `writer_avg_batch`, `max_queue_depth`, `queue_utilization`, and `backpressure`.
- Surface hybrid backpressure as `degraded` in `/healthz` without breaking the existing release health contract.
- Strengthen the E2E validator: any *new* dropped event or >=90% queue utilization during the validation window is now a FAIL rather than a warning.
- Add regression coverage for batched JSONL ordering and high-burst bridge throughput.

No detection recipe, lifecycle threshold, scoring rule, or Rust market-event schema is changed.
