# Scout v6.7.3 — Optimization Integrity Update

This release fixes three measurement gaps without changing the live detector.

## Recall audit corrections
- Separates movers already above +5/+10/+20/+50% at monitor start from true fresh crossings.
- Historical Scout findings older than the monitoring window no longer count as "seen before crossing."
- Move-consumption calculations only run when the measured event occurs after monitoring starts.
- Adds per-ticker blocker forensics and aggregate blockers for seen-but-nonactionable names.

## MIXED decomposition
The former flat MIXED bucket is now decomposed by:
- 5-minute direction: POSITIVE / NEGATIVE / FLAT
- 5-minute magnitude: TINY / SMALL / MEDIUM / LARGE
- 15-minute resolution: CONTINUATION / FADE / HELD / RECOVERY /
  PARTIAL_RECOVERY / DETERIORATION / HELD_NEGATIVE / RESOLVED_UP /
  RESOLVED_DOWN / CHOP / PENDING_15M

The broad `classification_family=MIXED` field remains for trend compatibility.

## Independent outcome validation
Adds a validation-only Alpha Vantage TIME_SERIES_INTRADAY adapter. It does not
feed the production detector. When configured with `ALPHAVANTAGE_API_KEY`,
detection-quality v6 computes an independent 1-minute OHLCV forward check and
records price/return/MFE/MAE deltas plus a tolerance verdict.

No detector thresholds, promotion rules, notification rules, or 24H logic are
changed by this release.
