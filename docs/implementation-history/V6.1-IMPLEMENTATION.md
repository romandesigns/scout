# StockHunter Scout 6.1.0

## Release objective

Make charts reliable after a restart and reduce Radar label congestion without weakening the evidence shown to the user.

## Chart data contract

`GET /api/market/snapshot/{ticker}` accepts `detected_at` and `bucket_seconds`.

The response source is one of:

1. `live` — current in-memory SIP/BOATS buckets cover the selected detection.
2. `historical-trades` — Alpaca historical trades aggregated to Scout's requested candle duration.
3. `historical-bars` — one-minute Alpaca bars used as the final closed-session fallback.

The UI always requests the original `detected_at`. Old findings stop polling after their initial historical load, preventing unnecessary Alpaca traffic.

## Chart interaction

- Mouse wheel: zoom candle density.
- Pointer drag: pan backward and forward through available candles.
- Hover: synchronized crosshair and OHLCV/trade-count tooltip.
- Double click: return to the 80-candle live-edge view.
- Existing formation, detection, catalyst, halt/resume, trigger, invalidation, EMA9, EMA21, VWAP, volume, price, and ET time annotations remain available.

## Icon language

Radar urgency and signal text badges use `react-icons/md`. Every icon has:

- a stable event-specific shape;
- semantic color;
- native and custom hover help;
- keyboard focus support;
- an accessible label.

Exact values—ticker, price, change, evidence, velocity, and relative volume—remain textual.

## Desktop cache safety

The browser/PWA continues registering `sw.js`. Tauri is detected independently and unregisters old workers and caches rather than registering the PWA worker inside the native WebView.
