# StockHunter Scout 6.4.0 — Historical Replay Calibration

## Purpose

V6.4 shortens the validation cycle by simulating historical Alpaca sessions now instead of waiting only for future live sessions. It begins the agreed Rust Market Intelligence migration while retaining Python as the production behavioral oracle until parity is proven.

## Architecture boundary

The Rust `scout-market-replay` crate owns deterministic event validation, source-time ordering, rolling market windows, and shadow pre-ignition candidate generation. Python continues to run the deployed detector and owns post-run calibration, catalysts, notification policy, delivery, Inspector data, and application coordination. Tauri remains the native desktop shell.

Both engines consume the identical `scout.market-event.v1` dataset. `compare_replay_parity.py` matches precursor ticker, timestamp, and recipe score. Rust is not permitted to replace live Python detection until parity is complete across representative sessions.

## Data acquisition

`run-calibration.ps1` accepts a date range and either explicit symbols or a bounded active-universe prefilter. The prefilter uses one-minute bars only to reduce download volume. Every selected candidate is then evaluated from raw historical trades by both engines; bar prefilter results do not qualify findings.

```powershell
pwsh -File .\run-calibration.ps1 -StartDate 2026-08-10 -EndDate 2026-08-14 -MaxSymbolsPerSession 40
```

For known examples:

```powershell
pwsh -File .\run-calibration.ps1 -StartDate 2026-08-10 -EndDate 2026-08-14 -Symbols "OPEN,LFS,ACHR,NXXT"
```

## Calibration contract

- Events are sorted by exchange source timestamp and sequence.
- The replay clock never reads wall time.
- Detection receives no future trade, outcome, or session label.
- Outcome scoring begins only after all detection events have been recorded.
- A calibration expansion is initially defined as +2% within 15 minutes, measured from the detection price.
- Missed expansion scanning uses a +2% release from a rolling five-minute low, deduplicated into 15-minute episodes.
- These definitions are calibration hypotheses and not probabilities or trading instructions.

## Report

Each run persists exact precursor outcomes, median lead time, false arms, missed expansions, maximum favorable 15-minute excursion, and ingredient success rates. The full Python report remains beneath `data/replays/<run-id>/report.json`; `rust-latest.json` contains Rust candidates; `parity-latest.json` records matches, missing candidates, extras, score agreement, and the production cutover gate.

## Safety

Replay has a capture-only dispatcher, a separate SQLite database, and no notification providers. Rust output is evidence-only and cannot enter live dispatch. `PRE_IGNITION` remains shadow-only. No new environment variables are introduced.
