# Scout v6.6.1 — Evidence-Driven Early Release

Production promotion tracing in v6.6.0 showed that 10 of 13 observed promotions were already
`late_risk`, while otherwise strong candidates were commonly held by `fresh_impulse` and
`first_leg_release`.

v6.6.1 adds a narrowly scoped early-notification path. It does **not** relax the CLEAN/bullish
quality requirement and does not alter later SURGE/BREAKOUT/IGNITION confirmation logic.

An early release requires:

- an existing structurally valid first-leg candidate;
- CLEAN + bullish-confirmed quality (`quality_actionable`);
- real participation;
- full warmup;
- quality score >= 82;
- fresh positive velocity >= 0.12%;
- base extension <= 0.75%;
- price still close to the micro trigger (-0.35% to +0.50%);
- candidate age <= 15 seconds.

When these gates pass before the legacy `first_leg_release`, Scout may emit an actionable `EARLY`
notification with the `EARLY_RELEASE` signal. Later higher-rank SURGE/BREAKOUT/IGNITION events
remain eligible as confirmation.

The promoted finding persists the complete `early_release` decision and whether the path was used,
so false-positive and late-risk rates can be measured directly after deployment.
