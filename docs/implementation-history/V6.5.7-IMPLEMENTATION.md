# Scout v6.5.7 — DB Contention + Async Isolation

v6.5.7 is a targeted reliability release based on production profiling from 2026-08-17.

Production `py-spy` captured the asyncio main thread blocked in `Store.seen()` from `alpaca_news_loop`, while executor workers were simultaneously running `latest_findings_by_ticker`, `list_attention/get_finding`, and `hybrid_precision_stats` through the same SQLite Store lock. SQLite query-plan inspection also showed `hybrid_precision_stats` performing a full `findings` scan plus a correlated `SCAN f2` with no `hybrid_key` index.

## Changes

- Adds `ix_findings_hybrid_key_time` on `(hybrid_key, detected_at, id)` after schema migration guarantees the column exists.
- Rewrites `hybrid_precision_stats()` to aggregate engine sources once instead of running a correlated full-table subquery for each episode.
- Adds atomic `Store.claim_seen()` to replace the two-lock `seen()` + `mark_seen()` catalyst dedupe sequence.
- Moves Alpaca news dedupe database work off the asyncio event-loop thread with `asyncio.to_thread()`.
- Uses the atomic claim path for SEC and RSS polling as well, reducing SQLite lock acquisitions.
- Retains the v6.5.6 event-loop watchdog and self-hosted ntfy service as safety layers.

Detection recipes, lifecycle thresholds, Rust candidate logic, ranking semantics, and notification policy are unchanged.
