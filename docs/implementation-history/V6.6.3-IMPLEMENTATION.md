# Scout v6.6.3 — Late Fresh-Promotion Suppression

v6.6.3 preserves the optimized v6.6.2 EARLY_SIGNAL and EARLY_RELEASE architecture and adds one narrow promotion-policy guard.

Repeated production traces showed that EARLY promotions were consistently non-late while a small set of later IGNITION/BREAKOUT promotions were still emitted after Scout itself marked them `late_risk=true`. The new guard prevents SURGE, BREAKOUT, and IGNITION from becoming a fresh actionable promotion when the existing late-risk boundary is crossed (`base_extension_pct > 0.75` or `extension_pct > 2.0`).

This is intentionally not a blanket stage block. Non-late BREAKOUT/IGNITION/SURGE candidates remain eligible. Explicit continuation/re-entry paths such as REARM, VWAP_RECLAIM, and EMA_RECLAIM remain eligible because they require their own pullback/reclaim structure. EARLY logic, evidence scoring, hard blockers, thresholds, and trace fields are unchanged.

The late-risk predicate is now shared by both tracing and promotion suppression so diagnostics and policy use the same boundary. Regression tests cover late suppression, fresh-stage preservation, re-entry exemptions, boundary parity, and EARLY preservation.
