# Scout v6.5.5 — Radar freshness and priority hardening

## Scope

v6.5.5 is a focused workstation UX release built on the v6.5.4 lifecycle fix.

### Radar count badges
- Actionable, Developing, and All tabs now show the count of rows actually available in each live bucket.
- Counts are derived from the same filtered collections the UI renders.

### Freshness policy
- Actionable radar rows are treated as live for 45 minutes from their latest detection.
- Developing radar rows are treated as live for 2 hours from their latest detection.
- Older persisted lifecycle records remain available through historical/Inspector surfaces but no longer occupy the live decision queue.

### Deterministic priority sorting
Radar rows are ordered by:
1. actionable rank (A > B > C)
2. lifecycle/stage urgency
3. quality score
4. evidence score
5. newest detection first

This prevents stale persisted candidates from outranking materially fresher candidates with otherwise comparable quality.

### Preserved behavior
- v6.5.4 Developing lifecycle mapping is preserved.
- v6.5.3 chart snapshot caching and symbol-switch responsiveness are preserved.
- No detector thresholds or Rust market-replay logic are retuned in this release.
