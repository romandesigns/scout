# Scout v6.5.4 implementation

## Radar lifecycle correctness

- Developing scope now follows lifecycle semantics instead of treating every CLEAN finding as actionable.
- `AWAKENING`, `PRE_IGNITION`, activity/watch stages, and shadow findings remain visible under Developing.
- Actionable scope is reserved for findings that have graduated beyond the developing/shadow lifecycle.
- Radar keeps a larger 300-symbol working set so active early candidates survive normal market churn longer.
- Episode retrieval now ranks the latest finding per ticker in SQLite before applying the response limit. This removes the old global-500-finding truncation failure mode that could make a recently notified symbol disappear from Radar.

## Responsiveness preservation

- Keeps the v6.5.3 immediate chart-prefetch and snapshot-cache path intact.
- SSE findings update Radar immediately and continue to reconcile with the authoritative episode endpoint.

## Release identity

- Application, web package, Tauri, service worker, and default backend version advanced to 6.5.4.
