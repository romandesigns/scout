# Scout v6.5.2 — Workstation UX, Chart Interaction, and Notification Consolidation

## Scope

v6.5.2 keeps the validated v6.5.1 Rust-primary + Python-specialist intelligence thresholds frozen. This release changes how Scout communicates, navigates, charts, and delivers user-facing alerts.

## UI primitive standard

- Native browser `<select>` controls are replaced by the shadcn/Base UI Select primitive.
- Native `title=` tooltips on interactive Scout controls are replaced with collision-aware shadcn/Base UI tooltips.
- Toolbar icon hints use portal-based overlays with viewport collision padding so tooltips do not block adjacent icons.
- Existing shadcn-style buttons, badges, switches, inputs, and tabs remain the interaction foundation.

## Chart workstation

- Wheel zoom, drag pan, two-finger pinch zoom, crosshair tracking, double-click Fit, and explicit +/-/Fit controls.
- Crosshair OHLCV readout is compact and outside the candle labels.
- Repeated finding annotations are clustered per candle; only the selected event gets a persistent text label.
- Cluster markers show a count and can be clicked/keyboard-activated to drive the Inspector selection.
- Delivery events are reduced to small state markers instead of repeated ALERT/QUEUE text.
- Formation regions, trigger levels, invalidation levels, and the selected detection remain distinct visual concepts.

## Unified selection / mobile Inspector

- A stock selection remains a single shared application state.
- Selecting a Radar stock on mobile immediately opens the chart/Inspector destination.
- Gainers, halts, catalysts, alerts, and chart event markers use the same selection pathway.
- Chart markers can update the active Inspector finding.

## Notification policy

- ntfy is the primary external Scout alert channel.
- Automatic Tauri/Windows native finding toasts are no longer queued from the live finding stream, preventing duplicate desktop OS alerts.
- The in-app Attention/notification center remains active.
- Resend/email is explicitly paused for this release; missing Resend configuration is not treated as an operational warning.
- PWA Web Push remains optional and opt-in so a phone using ntfy does not automatically receive duplicate alerts.
- Existing VAPID/Web Push server plumbing is retained. `scripts/generate-vapid.py` generates the two required VAPID environment values when PWA background push is intentionally enabled.

## Production observations carried forward

v6.5.1 production validation established full-universe feed health and a healthy Rust bridge, but also showed repeated PRE_IGNITION observations and duplicate ticker rows. v6.5.2 addresses the communication/visualization side of that behavior without altering frozen detector thresholds. Precision telemetry remains visible for subsequent intelligence evaluation.
