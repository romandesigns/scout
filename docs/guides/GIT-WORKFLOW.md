# Git workflow

Repository: `https://github.com/romandesigns/scout.git`  
Branch: `main`

## First extracted release

Run once from PowerShell 7:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\initialize-git.ps1
git status
git add .
git commit -m "Scout 6.0.0 Replay Spine"
git push -u origin main
```

`.env`, runtime databases, replay downloads, charts, build caches, installers and local recovery material are ignored. The repository tracks `.env.example`, source, tests, deployment scripts and CI configuration.

## Future releases

Extract the update into the existing clone so its `.git` directory remains in place. Then run:

```powershell
git status
git add .
git commit -m "Describe the Scout update"
git push origin main
```

Build and deploy only after the commit has been pushed successfully.

## Local configuration

The package contains a local `.env`, but Git intentionally ignores it. Values that cannot safely be embedded in a distributed archive remain blank:

- `ALPACA_API_KEY`
- `ALPACA_API_SECRET`
- `RESEND_API_KEY`
- `NTFY_TOPIC`
- `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY` until generated by deployment

Copy those values from the currently working Scout `.env`. Never add `.env` with `git add -f`.
